## 동기(Sync)부터 이해하자

비동기를 알려면 동기를 먼저 알아야 한다.

**동기(Synchronous)** 는 말 그대로 순서대로, 하나가 끝나야 다음이 시작되는 방식이다.

카페에 비유하면 이렇다.

```
손님 A 주문 → 커피 제조 → 완성 → 손님 B 주문 → 커피 제조 → 완성
```

A 커피가 다 나올 때까지 B는 주문도 못 한다. 줄이 하나씩 처리되는 것.

코드로 보면 이렇다.

```js
console.log("A 주문");
console.log("A 커피 제조 중..."); // A가 끝나야
console.log("A 완성");
console.log("B 주문"); // B가 시작됨
```

순서대로 위에서 아래로 실행된다. 직관적이고 예측하기 쉽다. 근데 문제가 있음.

---

## 동기 방식의 문제

만약 커피 제조에 5분이 걸린다면?

```js
const data = 서버에서_데이터_가져오기(); // 이게 3초 걸린다면...
console.log(data);
console.log("화면 보여주기"); // 3초 동안 이 줄은 실행도 못 함
```

**3초 동안 브라우저 전체가 멈춘다.** 버튼도 안 눌리고, 스크롤도 안 되고, 아무것도 못 한다. 이걸 **블로킹(Blocking)** 이라고 한다.

서버에서 데이터 받아오는 건 네트워크 상황에 따라 1초가 될 수도, 10초가 될 수도 있다. 그동안 사용자가 멍하니 기다려야 한다면? 그냥 창 닫아버릴 것 같다.

## 비동기(Async)란

**비동기(Asynchronous)** 는 기다리지 않고 다음 작업을 먼저 처리하는 방식이다.

카페로 다시 돌아가면.

```
손님 A 주문 → (제조 시작, 기다리는 동안)
손님 B 주문 → (제조 시작)
손님 C 주문 → (제조 시작)
A 커피 완성 → A에게 전달
B 커피 완성 → B에게 전달
```

진동벨을 주고 "다 되면 알려드릴게요" 하는 방식이다. 기다리는 동안 다른 일을 처리할 수 있음!

---

## JS가 비동기를 처리하는 방식

JS는 원래 **싱글 스레드**, 즉 한 번에 하나의 일밖에 못 한다. 그럼 어떻게 비동기 처리를 하는 걸까?

브라우저가 도와주는 것이다.

```
┌──────────────────────────────────────────────┐
│                   브라우저                    │
│                                              │
│  JS 엔진        Web APIs       이벤트 루프   │
│  (코드 실행)   (타이머,        (다 끝나면    │
│               네트워크 등)     JS에 알림)    │
└──────────────────────────────────────────────┘
```

JS가 "이거 시간 걸리는 작업이다" 싶으면 브라우저 Web API한테 넘긴다. 그동안 JS는 다음 코드를 계속 실행한다. 작업이 끝나면 브라우저가 JS한테 "다 됐어!" 하고 알려주는 구조임.

```js
console.log("시작");

setTimeout(function () {
  console.log("3초 후 실행"); // 브라우저한테 맡겨둠
}, 3000);

console.log("끝"); // setTimeout 기다리지 않고 바로 실행됨!

// 출력:
// 시작
// 끝
// (3초 후) 3초 후 실행
```

`setTimeout`을 브라우저한테 넘기고, JS는 바로 다음 줄로 넘어간다. 3초가 지나면 브라우저가 콜백 함수를 다시 JS한테 돌려준다.

---

## 비동기가 필요한 상황들

실제로 비동기 처리가 필요한 상황은 이렇다.

- **API 요청** — 서버에서 데이터 받아올 때 (얼마나 걸릴지 모름)
- **타이머** — `setTimeout`, `setInterval`
- **파일 읽기/쓰기** — Node.js 환경에서
- **이미지 로딩** — 이미지가 다 불러와지면 실행
- **사용자 이벤트** — 버튼 클릭, 키보드 입력 등

전부 "언제 끝날지 모르는" 작업들이다. 이걸 동기로 처리하면 그때마다 화면이 멈춰버리니까 비동기로 처리하는 것.

---

## 근데 순서가 보장이 안 되면 문제 아닌가?

맞다. 비동기의 가장 큰 난관이 여기에 있다.

```js
let userData;

fetch("/api/user") // 서버에 요청 (비동기)
  .then((res) => res.json())
  .then((data) => {
    userData = data;
  });

console.log(userData); // undefined! 아직 데이터가 안 왔음
```

비동기라서 데이터를 받기도 전에 `console.log`가 먼저 실행돼버린다.

그래서 "데이터 받은 다음에 이걸 실행해줘"라고 명시해야 하는데, 그게 바로 **콜백, Promise, async/await** 이다.

---

## 정리

|           | 동기             | 비동기                  |
| --------- | ---------------- | ----------------------- |
| 실행 방식 | 순서대로, 하나씩 | 기다리지 않고 다음 실행 |
| 블로킹    | 있음             | 없음                    |
| 순서 보장 | 됨               | 별도 처리 필요          |
| 사용 상황 | 일반 코드 흐름   | API, 타이머, 이벤트     |

## 오늘 얻은 것

비동기 자체가 어려운 게 아니라 **"기다리지 않는다"** 는 개념이 처음엔 낯선 것 같음. 진동벨 받고 자리에 앉는 것처럼, JS도 작업을 맡겨두고 다른 일을 먼저 한다고 생각하면 됐다.

다음 편은 비동기를 실제로 코드로 다루는 방법 **콜백 지옥이 왜 생기고, Promise가 어떻게 해결했고, async/await이 뭔지** 까지 이어서 정리해볼 예정이다.

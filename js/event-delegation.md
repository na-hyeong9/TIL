# [JS] - 1 - 이벤트 위임(Event Delegation), 버블링을 이용한 효율적인 이벤트 처리

> 2026.07.23

---

## 지난 편에서

CSS 시리즈에서 `transition`과 `animation`으로 움직임을 다뤘다. 예고했던 대로 이번엔 JS로 넘어와서, 리스트나 테이블처럼 요소가 많은 화면에서 이벤트를 어떻게 효율적으로 처리하는지 — 이벤트 위임을 정리한다.

---

## 이벤트 버블링부터

이벤트 위임은 이벤트 버블링(bubbling)을 전제로 한다. 자식 요소에서 발생한 이벤트는 부모 방향으로 계속 전파된다.

```js
document.querySelector('ul').addEventListener('click', (e) => {
  console.log(e.target); // 실제 클릭된 요소
});
```

`li`마다 리스너를 따로 걸지 않고 `ul` 하나에만 걸어도, `li`를 클릭하면 이벤트가 `ul`까지 버블링되면서 잡힌다. 자식 100개가 있어도 리스너는 1개면 충분하다.

---

## target vs currentTarget

`e.target`은 실제로 이벤트가 발생한 요소이고, `e.currentTarget`은 리스너가 붙어있는 요소다. 위임 패턴에서는 이 둘이 다르다는 걸 항상 의식해야 한다. 어떤 `li`를 클릭했는지 알려면 `target`을 써야 하고, `target`이 `li` 자체가 아니라 그 안의 `span` 같은 자식일 수도 있으므로 `closest()`로 원하는 조상까지 찾아 올라가는 게 안전하다.

```js
list.addEventListener('click', (e) => {
  const item = e.target.closest('li');
  if (!item) return;
  console.log(item.dataset.id);
});
```

---

## 왜 쓰는가

1. 동적으로 추가되는 요소 처리 — `li`를 나중에 추가해도 새로 리스너를 걸 필요가 없다.
2. 메모리 절약 — 요소 100개에 리스너 100개 대신 부모에 1개만 두면 된다.
3. 리스너 관리 단순화 — 제거할 때도 하나만 신경 쓰면 된다.

단점도 있다. 모든 이벤트가 버블링되는 건 아니다. `focus`, `blur`는 버블링되지 않아서 위임하려면 `focusin`/`focusout`으로 대체해야 한다. 그리고 자식 쪽 핸들러에서 `stopPropagation()`을 호출하면 부모까지 이벤트가 도달하지 못해 위임 자체가 깨지므로, 정말 필요한 경우가 아니면 쓰지 않는 게 좋다.

---

## 오늘 얻은 것

이벤트 위임은 "이벤트를 어디서 잡을까"를 자식 각각이 아니라 공통 부모로 옮기는 전략이다. `target`으로 실제 클릭 대상을 찾고 `closest()`로 원하는 조상까지 올라가는 조합이 실무에서 가장 자주 쓰인다. 다음엔 다시 퍼블리셔 쪽으로 돌아와 **반응형 이미지(srcset, picture)**를 다뤄볼 예정이다.

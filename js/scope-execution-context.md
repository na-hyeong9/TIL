# TIL | 스코프 & 실행 컨텍스트 JS가 코드를 읽는 방식

> 2026.04.09

## 계기

`var`로 선언한 변수가 블록 밖에서도 살아있는 걸 보고 "어? 왜?"라고 생각한 적이 한두 번이 아니다. 알고 보니 스코프랑 실행 컨텍스트를 모르면 JS 동작 방식을 절반도 이해 못 하는 거였다. 그게 바로 나다.

---

## 실행 컨텍스트가 뭔가

JS 엔진이 코드를 실행할 때, 그 코드가 동작하는 **환경 정보를 담은 객체**라고 보면 된다. 함수가 호출될 때마다 새로운 실행 컨텍스트가 생기고 이게 **콜 스택(Call Stack)** 위에 쌓인다.

```
전역 실행 컨텍스트
└── greet() 호출 → greet 실행 컨텍스트 생성
    └── getName() 호출 → getName 실행 컨텍스트 생성
```

함수 실행이 끝나면 해당 컨텍스트는 스택에서 제거된다. 단순하지만 이걸 모르면 호이스팅이나 클로저가 왜 그렇게 동작하는지 설명이 안 됐다.

실행 컨텍스트 안에는 크게 세 가지가 들어있다.

- **Variable Environment** 변수, 함수 선언 저장
- **Lexical Environment** 스코프 체인 정보
- **this 바인딩** 현재 컨텍스트에서 this가 뭔지

## 스코프

스코프는 **변수에 접근할 수 있는 범위**다. JS는 크게 세 가지 스코프가 있다.

### 전역 스코프

코드 어디서든 접근 가능한 변수다. 근데 전역 변수는 남용하면 충돌 위험이 크고 디버깅이 힘들어짐. 최대한 안 쓰는 게 맞다.

```js
var globalVar = "나는 전역이다";

function test() {
  console.log(globalVar); // 접근 가능
}
```

### 함수 스코프

`var`로 선언한 변수는 **함수 단위**로 스코프가 생긴다. 블록(`{}`)이 아니라 함수 기준이라는 게 핵심임.

```js
function test() {
  var x = 10;
  if (true) {
    var x = 20; // 같은 함수 스코프라 덮어씌워진다
  }
  console.log(x); // 20  의도하지 않은 결과
}
```

### 블록 스코프

`let`, `const`는 **블록(`{}`) 단위**로 스코프가 생긴다. 예측 가능하고 안전하다.

```js
function test() {
  let x = 10;
  if (true) {
    let x = 20; // 블록 안에서만 유효함
  }
  console.log(x); // 10  이게 맞지!
}
```

## 호이스팅

실행 컨텍스트가 생성될 때, JS 엔진은 코드를 실행하기 **전에** 변수 선언과 함수 선언을 먼저 메모리에 올린다. 이게 호이스팅이다.

### `var`의 호이스팅

선언 자체는 올라가는데, **초기화(값 할당)는 안 올라간다.** 그래서 선언 전에 접근하면 `undefined`가 나옴.

```js
console.log(name); // undefined  에러가 아니라 undefined다!
var name = "김코딩";
console.log(name); // '김코딩'
```

엔진 입장에서는 이렇게 읽는 거랑 같다.

```js
var name; // 선언이 위로 올라감
console.log(name); // undefined
name = "김코딩";
console.log(name); // '김코딩'
```

### `let` / `const`의 TDZ

`let`과 `const`도 호이스팅은 된다. 근데 **TDZ(Temporal Dead Zone, 일시적 사각지대)** 때문에 선언 전에 접근하면 에러가 난다.

```js
console.log(name); // ReferenceError! TDZ 구간이다.
let name = "김코딩";
```

선언은 됐지만 초기화가 안 된 상태라 접근 자체를 막아버리는 것. 오히려 이게 더 안전하다. `var`처럼 조용히 `undefined` 뱉는 것보다 에러로 알려주는 게 훨씬 낫다.

### 함수 선언식 vs 함수 표현식

```js
// 함수 선언식 : 통째로 호이스팅됨
greet(); // '안녕!' 선언 전에도 호출 가능하다.
function greet() {
  console.log("안녕!");
}

// 함수 표현식 : 변수만 호이스팅, 함수 본체는 안 올라감
hello(); // TypeError! hello는 undefined 상태다.
var hello = function () {
  console.log("안녕!");
};
```

함수 표현식을 `const`로 선언하면 TDZ가 적용돼서 `ReferenceError`가 남. 어느 쪽이든 선언 전 호출은 피하는 게 맞다.

## 스코프 체인

함수 안에서 변수를 찾을 때, 현재 스코프에 없으면 **바깥 스코프**로 올라가면서 찾는다. 이 과정이 체인처럼 연결되어 있어서 스코프 체인이라고 부름.

```js
const outer = "외부";

function outerFn() {
  const inner = "내부";

  function innerFn() {
    console.log(outer); // 바깥 스코프에서 찾아옴 '외부'
    console.log(inner); // 부모 스코프에서 찾아옴 '내부'
  }

  innerFn();
}
```

전역 스코프까지 올라갔는데도 없으면 그때 `ReferenceError`가 난다.

## 렉시컬 스코프

JS는 **렉시컬 스코프(정적 스코프)** 방식이다. 함수가 **어디서 호출됐는지**가 아니라, **어디서 정의됐는지**를 기준으로 스코프가 결정된다는 뜻임.

```js
const x = "전역";

function printX() {
  console.log(x); // 정의된 위치의 스코프 기준
}

function test() {
  const x = "지역";
  printX(); // '전역'  test 안에서 호출됐지만, printX는 전역에서 정의됐음
}

test();
```

이 개념이 클로저의 기반이 된다. 함수가 정의될 때 스코프를 "기억"하고 있는 게 클로저다.

## 오늘 얻은 것

"변수는 그냥 쓰면 되는 거 아닌가"라고 생각했는데, JS 엔진이 코드를 어떤 순서와 범위로 처리하는지 알고 나니까 버그가 왜 생기는지 설명이 되기 시작함.

`var` 쓰지 말라는 이유, `let`/`const`가 더 안전한 이유, 함수 선언식을 남용하면 안 되는 이유 전부 실행 컨텍스트랑 스코프를 알면 자연스럽게 연결된다.

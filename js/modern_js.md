# TIL | 모던 JS와 전통 JS의 차이점, 그리고 왜 써야 하나

> 2026.04.08

---

## 계기

예전 프로젝트 코드를 보다가 `var`로 범벅된 레거시 코드를 또 마주쳤다. 만들 땐 바쁘다고 그냥 넘겼는데, 지금보니 코드가 엉망이라 찜찜해서 정리해보기로 했다.... 정확히 왜 `let`을 써야하는지는 모르고 다음 프로젝트를 진행했는데 정확히 알고 넘어가고 싶었다.

---

## 모던 JS가 뭔데?

ES6(ES2015) 이후로 나온 자바스크립트 문법을 통틀어서 "모던 JS"라고 부른다. `let`, `const`, 화살표 함수, 구조 분해 할당, 옵셔널 체이닝... 이런 것들이 다 여기에 속한다.

그 전에 쓰던 방식은 흔히 "바닐라 JS" 또는 그냥 "전통 JS", "레거시 JS"라고 부르는 편이다.

---

## 뭐가 달라졌나

### 1. 변수 선언: `var` → `let` / `const`

전통 JS에서는 무조건 `var`였다. 근데 `var`는 **함수 스코프**라서 블록 밖으로 튀어나오는 경우가 생긴다. 진짜 버그 찾기 힘들었다.

```js
// 전통 방식
var x = 10;
if (true) {
  var x = 20; // 같은 x를 덮어써버림!
}
console.log(x); // 20 — 의도하지 않은 결과

// 모던 방식
let x = 10;
if (true) {
  let x = 20; // 블록 안에서만 유효
}
console.log(x); // 10 — 예측 가능!
```

`const`는 재할당 불가라서 변하지 않는 값에는 무조건 써주는 게 맞다. 명시적으로 "이건 안 바뀌는 값이야"라고 선언하는 셈이니까 코드 읽기가 훨씬 편해진다.

---

### 2. 함수 표현식: 일반 함수 → 화살표 함수

```js
// 전통 방식
var add = function(a, b) {
  return a + b;
};

// 모던 방식
const add = (a, b) => a + b;
```

짧아진 것도 좋은데, 진짜 핵심은 `this` 바인딩이 다르다는 거다. 화살표 함수는 자체적인 `this`를 갖지 않고 외부 스코프의 `this`를 그대로 가져온다. 그래서 이벤트 핸들러나 콜백 안에서 `this`가 날아가버리는 문제를 훨씬 줄일 수 있음!

---

### 3. 비동기 처리: 콜백 → Promise → async/await

전통 JS에서 비동기 처리를 하다 보면 콜백이 중첩되고 중첩되고... 이른바 "콜백 지옥"이 펼쳐진다.

```js
// 전통 방식 — 콜백 지옥
getData(function(a) {
  getMoreData(a, function(b) {
    getEvenMoreData(b, function(c) {
      console.log(c);
    });
  });
});

// 모던 방식 — async/await
const result = await getEvenMoreData(await getMoreData(await getData()));
console.log(result);
```

`async/await` 쓰면 비동기 코드가 동기 코드처럼 읽힌다. 유지보수할 때 좋다고 한다.

---

### 4. 구조 분해 할당 (Destructuring)

```js
// 전통 방식
var name = user.name;
var age = user.age;

// 모던 방식
const { name, age } = user;
```

배열도 된다.

```js
const [first, second] = [1, 2];
```

React 쓰다 보면 이거 없이는 못 산다. `useState` 쓸 때부터 바로 나오니까.

---

### 5. 템플릿 리터럴

```js
// 전통 방식
var greeting = "안녕, " + name + "! 나이는 " + age + "살이네.";

// 모던 방식
const greeting = `안녕, ${name}! 나이는 ${age}살이네.`;
```

비교해보니 확실히 모던 방식이 문자열 조합 코드가 눈에 확 들어온다.

---

## 모던 JS를 써야 하는 이유

1. **가독성** — 코드가 짧고 의도가 명확하다. 나중에 내가 봐도 이해가 되고, 팀원도 이해가 된다.
2. **안전성** — `var` 호이스팅, `this` 바인딩 같은 함정이 줄어든다.
3. **생태계** — React, Vue, TypeScript 전부 모던 JS 기반이다. 레거시 문법만 알면 프레임워크 쓸 때 계속 막힘.
4. **성능** — 엔진 최적화가 `let/const` 기반으로 더 잘 된다고 알려져 있음.

---

## 그래서 오늘 얻은 것

레거시 코드가 무조건 나쁜 건 아니다. 근데 신규 코드를 짤 때 굳이 `var`를 쓸 이유는 없다. 모던 JS는 그냥 편의 기능이 아니라, **더 예측 가능하고 유지보수하기 좋은 코드**를 쓰기 위한 기반이다.

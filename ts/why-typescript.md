# TIL | TypeScript를 쓰는 이유 — JS랑 뭐가 다른가

> 2026.04.11

---

## 계기

포트폴리오 사이트를 TypeScript로 만들면서 `string`이니 `number`니 타입을 일일이 써줘야 하는 게 왜 필요한가 싶었음. 그냥 JS로 짜면 안 되나? 근데 쓰다 보니까 "아, 이래서 쓰는구나" 하는 순간이 왔다. 바로 오류 잡기!

---

## JS의 문제

JS는 **동적 타입 언어**다. 변수에 어떤 타입이든 넣을 수 있고, 실행 전까지는 타입 오류를 알 수 없었다.

```js
function add(a, b) {
  return a + b;
}

add(1, 2); // 3 — 의도한 결과다.
add(1, "2"); // '12' — 에러가 아니라 문자열 연결이 된다!
add(undefined, 2); // NaN — 조용히 NaN이 나온다.
```

에러도 안 나고 그냥 조용히 이상한 값이 나온다. 소규모 프로젝트는 그냥 넘어갈 수 있는데, 코드가 커지니까 어디서 어떤 타입이 들어올지 모르는 게 문제가 된다.

---

## TS가 해결하는 것

TypeScript는 JS에 **타입 시스템**을 더한 언어다. 정확히는 JS의 **슈퍼셋(Superset)** 이라서, 모든 JS 코드는 TS에서도 동작한다. 거기에 타입 선언을 얹은 것.

```ts
function add(a: number, b: number): number {
  return a + b;
}

add(1, 2); // 3
add(1, "2"); // 에러! — 컴파일 전에 잡아준다.
```

실행하기 전, **코드를 작성하는 시점에** 잘못된 타입 사용을 잡아낸다는 게 핵심이다. 런타임 에러가 되기 전에 이미 빨간 줄로 알려준다!

---

## 체감되는 차이들

### 자동완성이 달라진다

타입을 알고 있으니까 에디터가 훨씬 정확한 자동완성을 제안해준다. 객체 프로퍼티 접근할 때 `.` 찍으면 뭐가 있는지 바로 나온다. JS에서는 그냥 외워야 했던 것들이다.

```ts
interface User {
  name: string;
  age: number;
  email: string;
}

const user: User = { name: '김코딩', age: 26, email: 'test@test.com' };
user. // name, age, email 자동완성이 바로 뜬다!
```

### 리팩토링이 편해진다

함수 파라미터 이름을 바꾼다거나, 객체 구조를 변경할 때 TS가 영향받는 모든 곳을 잡아준다. JS에서는 수동으로 전부 찾아다녀야 했다.

### 협업할 때 문서 역할을 한다

타입 선언 자체가 **함수 명세서**가 된다. 이 함수가 어떤 데이터를 받고 뭘 반환하는지, 주석 없이도 타입만 보면 바로 파악되었다.

```ts
// 이 함수가 뭘 받고 뭘 반환하는지 한눈에 보인다
function getUserProfile(userId: string): Promise<User> { ... }
```

## JS vs TS 핵심 비교

| 항목           | JS                 | TS                   |
| -------------- | ------------------ | -------------------- |
| 타입 선언      | 없음               | 명시적 선언          |
| 오류 발견 시점 | 런타임 (실행 중)   | 컴파일타임 (작성 중) |
| 자동완성 품질  | 보통               | 정확함               |
| 러닝 커브      | 낮음               | 초반에 조금 있음     |
| 협업           | 암묵적 이해 필요   | 타입이 문서 역할     |
| 실행           | 브라우저 직접 실행 | JS로 컴파일 후 실행  |

---

## 오해하기 쉬운 것들

### "TS는 JS가 아니다?"

아니다. TS는 JS의 슈퍼셋이다. 결국 브라우저는 TS를 못 읽으니까 컴파일하면 JS가 된다. TS로 짠 코드는 전부 JS로 변환돼서 실행됨.

### "`any` 쓰면 TS 의미 없다"

맞다. `any`는 타입 검사를 포기하는 것과 같음. 처음에 어렵다고 `any`로 도배하면 JS랑 달라지는 게 없어진다. `unknown`이나 명확한 타입으로 최대한 좁혀가는 게 맞다.

### "소규모 프로젝트엔 과함?"

취향 차이가 있긴 한데, 혼자 짜는 프로젝트도 TS 쓰는 게 습관 들이기 좋다고 생각함. 나중에 돌아봤을 때 내 코드도 "이게 뭐지?"가 안 나오니까.

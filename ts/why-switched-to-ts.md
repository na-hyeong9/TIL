# [Growth] 익숙한 jsx를 버리고, 안전한 TSX로



## 1. Intro: "잘 돌아가는데 왜 고쳐?"에 대한 대답

내 포트폴리오의 `About` 페이지는 원래 `jsx`로 작성되었고, 애니메이션도 문제없이 작동했다.
익숙한 방식으로 빠르게 완성했지만, 마음 한구석엔 **"이게 정말 최선일까?"**라는 의문이 있었다.
프론트엔드 개발자로서 한 단계 성장하기 위해선 **'돌아가는 코드'**를 넘어 **'단단한 코드'**를 짜야 한다고 생각했고, 가장 익숙했던 `About.jsx` 파일을 **TypeScript(`About.tsx`)**로 리팩토링하는 도전을 시작했다.



## 2. Before & After: 코드가 어떻게 변했는가?

가장 큰 변화는 **'모호함'이 사라지고 '명확함'이 생겼다**는 점이다.

### 1) useRef의 변화: "너는 누구니?"
JSX에서는 `ref`가 무엇을 가리키는지 알 수 없었지만, TSX에서는 **"이것은 HTML 태그다"**라고 명찰을 달아주었다.

* **[Before: About.jsx]**
  
    ```javascript
    const aboutRef = useRef(); // 비어있음 (뭐가 들어올지 모름)
    ```
    
* **[After: About.tsx]**
    ```typescript
    // "이 ref에는 무조건 HTMLElement가 들어온다"고 명시
    const aboutRef = useRef<HTMLElement>(null);
    ```



### 2) 데이터 처리의 변화: "만약 값이 없으면?" (결정적 차이 ⭐)

GSAP 애니메이션에 `data-level` 값을 넣어주는 로직에서 TS의 진가가 발휘되었다.

* **[Before: About.jsx]**
  
    ```javascript
    // 값이 없어도 에러 없이 실행됨 (나중에 화면에서 0%가 아니라 빈칸으로 깨짐)
    width: (i, target) => target.dataset.level, 
    ```
    
* **[After: About.tsx]**
  
    ```typescript
    // TS Error: "값이 undefined일 수 있습니다." 경고 발생
    // -> 값이 없을 때를 대비해 "0%"라는 안전장치를 추가함
    width: (_: number, target: HTMLElement) => target.dataset.level || "0%",
    
    ```

* `_`: 사용하지 않는 인자는 언더바로 처리하여 의도를 명확히 함.   

* `target: HTMLElement`: 타겟이 HTML 요소임을 보장함.  

* `|| "0%"`: 데이터가 비어있을 때 프로그램이 멈추지 않도록 안전장치 마련.

  

## 3. 깨달음: 빨간 줄은 적이 아니었다

처음 `About.tsx`로 파일명을 바꾸자마자 뜬 수많은 빨간 줄(Type Error)은 나를 당황하게 했다.
하지만 코드를 수정해 나가면서, 그 빨간 줄들이 **"나중에 발생할 버그를 미리 알려주는 신호"**라는 것을 깨달았다.

만약 JSX 그대로 두었다면, 나중에 데이터가 실수로 누락되었을 때 애니메이션이 멈추거나 레이아웃이 깨졌을 것이다.
하지만 TSX로 바꾸는 과정에서 **예외 처리(`|| "0%"`)**를 강제받았고, 덕분에 내 코드는 훨씬 안전해졌다.



## 4. 결론 (Today I Learned)

익숙함에 안주했다면 `About.jsx`는 그저 '동작하는 파일'로 남았을 것이다.
하지만 TSX로 도전한 덕분에, 나는 **데이터의 흐름과 예외 상황을 예측하고 고민**할 수있는 계기가 되어 좋았다.
앞으로 남은 프로젝트의 모든 컴포넌트도 TypeScript 기반으로 설계하여, **신뢰할 수 있는 코드**를 만들도록 해야겠다.
